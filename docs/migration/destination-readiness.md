## Migrations created (one consolidated migration)

- Added enums `migration_run_status`, `migration_row_status`, `migration_validation_status`.
- Created control tables: `migration_runs`, `migration_entity_results`, `migration_rejections`.
- Created 8 mapping tables with an identical shape (all requested columns present): `legacy_identity_map`, `legacy_organization_map`, `legacy_position_map`, `legacy_candidate_map`, `legacy_application_map`, `legacy_submission_map`, `legacy_file_map`, `legacy_score_map`.
- Added provenance columns (`legacy_source_system`, `legacy_source_table`, `legacy_source_id`, `migrated_at`, `migration_run_id`, `migration_version`, `migration_status`) to 19 destination tables: `profiles`, `organizations`, `memberships`, `positions`, `screening_questions`, `candidate_profiles`, `applications`, `application_answers`, `candidate_matches`, `files`, `candidate_evidence`, `score_runs`, `client_decisions`, `interviews`, `messages`, `notifications`, `audit_events`, `intake_submissions`, `consent_records`.
- `updated_at` touch trigger applied to every new mapping/control table.

## Constraints created

| Constraint | Purpose |
|---|---|
| `PK` on every new table | row identity |
| `UNIQUE (source_system, source_table, source_id)` per mapping table | one legacy row → one destination row (idempotency) |
| `UNIQUE (destination_table, destination_id)` per mapping table (partial) | destination cannot be claimed twice |
| `FK migration_run_id → migration_runs(id) ON DELETE CASCADE` on results/rejections/every mapping | tenant of the run cascades cleanup |
| `UNIQUE (migration_run_id, entity)` on `migration_entity_results` | one roll-up per entity per run |
| `UNIQUE (legacy_source_table, legacy_source_id)` (partial) on all 19 destination tables | provenance idempotency guard |
| `UNIQUE (position_id, candidate_profile_id)` on `candidate_matches` | role-specific submission identity |
| Existing `tg_score_runs_identity` trigger | never reuse a score across positions |
| Existing `tg_score_runs_immutable` trigger | historical scoring runs preserved |
| `files.sha256` index (when column present) | Storage content identity for dedupe |
| Deny-all RLS policies on all 11 migration tables | no anon/authenticated access, no service-role bypass on domain tables |

## RLS results

- **Migration control + mapping tables (11):** RLS enabled AND `FORCE ROW LEVEL SECURITY`; explicit `deny_all_<table>` policy for `anon` and `authenticated` (`USING (false) WITH CHECK (false)`). `service_role` has `ALL` and bypasses RLS by design. Import can only be executed server-side under service role.
- **Existing domain tables:** untouched. No policy was dropped, weakened, or replaced. Provenance columns were added but no policy references them; existing tenant/owner rules continue to apply.
- **Linter:** all 14 warnings emitted by the linter are pre-existing (extensions in `public` schema; `SECURITY DEFINER` functions executable by signed-in users — these are the `has_role`, `is_org_*`, `is_active_user`, `is_owning_candidate`, `is_platform_staff`, `has_org_role`, `scoring_readiness` helpers created in earlier phases). This migration did not introduce them and does not resolve them; they are tracked separately.
