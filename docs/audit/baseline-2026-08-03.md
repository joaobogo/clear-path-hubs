## Defects found in the baseline (recorded, not fixed)

1. **`/login` renders two `<h1>` and two `<main>` at 390 px and 768 px** (both read "Sign in to TaaSFlow"). At 1440 px there is exactly one of each, so a responsive branch renders both a mobile and a desktop shell rather than switching between them. Highest-value fix in this baseline: duplicate landmarks break screen-reader navigation.
2. **React hydration mismatch errors** on `/industries`, `/jobs` and `/trust` at 390 px ("A tree hydrated but some attributes of the server rendered HTML didn't match the client properties"). No errors at 768/1440, so the mismatch comes from a viewport- or client-only branch. Needs isolation per route.
3. **`/blog`: 24 card links reported with no accessible name** by text-content measurement (`<a class="block" href="/blog/…">` wrapping a card). Requires manual confirmation with the accessibility tree — the wrapper may compute a name from card content that the DOM snapshot did not see.
4. **`/contact` (2) and `/intake` (3) controls without an accessible name.** These are Radix checkbox buttons and a hidden file input whose names come from associated `<label>` elements; treat as probable false positives pending an axe-core check, which previously reported zero violations on both pages.

## Expected-behaviour notes (not defects)

- `robots: noindex,follow` appears on most pages because `src/routes/__root.tsx` injects a preview guard on any host that is not `taasflow.com`/`www.taasflow.com`. On localhost that guard always fires, so this baseline cannot observe production robots values. Four pages (`/`, `/solutions`, `/case-studies`, `/blog`) recorded no robots meta at all, which is a timing race between the snapshot and that effect, not a configuration difference.
- Canonicals all point at `https://taasflow.com/<path>` and are self-referencing, matching `public/robots.txt`, `src/routes/sitemap[.]xml.ts` and the canonical-host redirect middleware in `src/start.ts`.

## Method

Chromium headless, `is_mobile`/`has_touch` enabled below 768 px, 2.2 s settle after `domcontentloaded`. Overflow is measured as `documentElement.scrollWidth > clientWidth + 2` plus per-element bounding-box checks that ignore fixed-position elements and any ancestor with a non-visible `overflow-x`. Console `error` messages and uncaught page errors are captured per navigation.
