MINOR F8 — Processing states have no pinned domain, so the label map has drifted from reality src/lib/vocabulary.ts (source-confirmed; partially observed) Problem PROCESSING_STATUS_VOCABULARY knows five values: queued, processing, completed, failed, skipped . The states the product actually stores and queries include parsing, parsed, enriching, ready_to_score, scoring, scored, manual_review_required, ocr_required — only queued overlaps. Unknown values fall through statusLabel() to sentenceCase() , which is why the UI reads ocr required and manual review required rather than a designed label. Root cause The same file solves this properly for positions: it warns that POSITION_STATUS_VOCABULARY is display-only and pins the real domain in POSITION_STATUS_VALUES , tested against the migrations. There is no PROCESSING_STATE_VALUES equivalent. F2 is the direct consequence — a filter written by hand against a domain nothing pins. LOVABLE PROMPT Add PROCESSING_STATE_VALUES to src/lib/vocabulary.ts listing the real processing_state enum from the migrations (including ocr_required and manual_review_required), pin it with a test mirroring tests/unit/position-status-enum.test.ts, give each value a proper client and candidate label in PROCESSING_STATUS_VOCABULARY, and refactor every hand-written processing_state array — starting with in_review_by_taasflow in client-overview.functions.ts — to derive from it.
